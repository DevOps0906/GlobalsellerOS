description: 프로토타입(prototype/index.html)의 화면과 apps/web 구현 차이 점검
---
인자: 화면 ID (`S-01` ~ `S-11`, 또는 `all`). 예: `/sync-design S-05`

1. `docs/설계/DESIGN_STRUCTURE.md` 1장 표에서 화면 ID 의 라우트와 "프로토타입 요소"(예: S-05 → `/orders`, `#view-orders`)를 찾는다. `all`이면 S-09(제품에서 제외)를 뺀 전체.
2. `prototype/index.html`에서 그 요소의 구조를 읽는다: 페이지 헤더 버튼, 하위 탭 · 마켓 탭, KPI 항목, 표 열, 상태 표시, 빈 상태 문구, 모달 단계. 큰 파일이므로 해당 `id` 구간만 읽는다(필요하면 사원 sub-agent-2 에게 추출을 맡긴다).
3. 같은 화면의 기획 정본 `docs/기획서/03_SCREENS_UX.md`의 화면 명세를 함께 본다. 프로토타입과 기획서가 다르면 기획서가 우선이고, 차이는 따로 적는다.
4. `apps/web/app/(app)/<라우트>/`와 관련 `components/`의 구현과 비교한다. 마켓 탭 화면(S-04 · S-05 · S-06)은 `MarketScope` 공통 컴포넌트 사용 여부와 `market` 쿼리 동작도 본다.
5. 화면별로 "명세 항목 / 프로토타입 / 기획서 / 구현 여부 / 차이" 표를 만든다. 반응형 3구간(375 · 1024 · 1440) 차이가 보이면 함께 적는다.
6. 코드는 고치지 않는다. 필요한 작업은 `tasks/README.md`의 "발견한 문제" 표에 제안으로 적을지 사용자에게 묻는다.
